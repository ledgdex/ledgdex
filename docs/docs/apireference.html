API REFERENCE


Ledgdex is a Python package (ledgdex, in py/) and a JavaScript core (js/) that make the same bytes, ids, signatures and state. Signatures and descriptions below are generated from the code. Start with Example: Python API, Example: JavaScript and Extending Ledgdex; the format is in Ledger File Format and the specification.

Python: ledgdex.core, ledgdex.canon, ledgdex.state, ledgdex.dex, ledgdex.render, ledgdex.check, ledgdex.publish, ledgdex.cli, ledgdex.sig.

ledgdex.core: Messages, entries and ledgers: signing, verifying, reading a ledger (spec 2, 3).

class ledgdex.core.Ledger(data, cache=True, root=None)

A parsed ledger. Verification stops at the first structurally invalid line (spec 3.3).

Verified prefixes are cached (in ~/.cache/ledgdex, by ledger id, length and SHA-256 of the exact bytes), so a ledger that only grew is verified only from where it was verified before. Any changed byte misses the cache and is verified in full. cache=False, or LEDGDEX_NO_CACHE=1, always verifies everything.

ledgdex.core.check_receipt(body, root=None)

A receipt verifies on its own (spec 5.1, invariant 10): the entry is signed by the other ledger's header key, or by a key that the key entries in "keys" (rotate, device, device_revoke, recovered, in order) lead to. A "recovered" key entry is checked against the root, as in the ledger itself: without it anyone could hand the other ledger to a key of their own and sign a false receipt.

ledgdex.core.root_recovers(root, ledger_id, e, prior=())

Spec 5.7: a "recovered" entry e of ledger ledger_id is signed by the new key, which a "recover" entry in the root names. A recover entry is spent by its first "recovered" (prior: the ledger's earlier key entries). Nothing the ledger's own keys do can void it: they may be a thief's, and entry times are theirs to choose. Raises Invalid otherwise.

ledgdex.state: The state function: a ledger replayed into one JSON object (spec 6).

ledgdex.state.state(led, root=None, now=None)

Replay a parsed Ledger. root: the root Ledger, for "allow": "admitted" (spec 5.7). now: the time auction statuses are judged at (default: the time of the last entry).

ledgdex.state.judged_at(m, entry_time)

When a claim or bid is judged against the root (spec 5.7), in seconds: the later of the time its author signed it (msg.at, which the seller cannot move) and the time the seller recorded it less the allowed skew (which the buyer cannot move back: a revoked key cannot buy by dating its claim before the revoke). Never a later root entry: a past claim stays as it was judged.

ledgdex.state.admissions(root)

The root's admit and revoke entries in order, as {key: [(seconds, admitted)]} (a message recorded twice counts once, as in 6.2). A claim or bid is judged by the root's admissions at judged_at() (spec 5.7).

ledgdex.state.admitted_at(admits, key, t)

Whether the root had admitted key at time t (seconds).

ledgdex.dex: A ledgdex on disk: keys, this dex's ledger, and reading other ledgers.

ledgdex.dex.load(dex, root=None)

ledgdex.dex.record(dex, msgs, at=None, secret=None, root=None, skipped=None)

Record messages in this dex's ledger. Only appends. Returns the entry ids. Signed with secret, or with the key signer() picks. skipped: a list to collect (message, reason) for messages that cannot be recorded (one counterparty's message signed in the future must not stop the rest); without it, the first one raises.

ledgdex.dex.fetch(src, cache=True, root=None, remote=False)

Read a ledger from a dex folder, a file, or a dex URL. Returns (Ledger, url). remote: src came from a ledger (a receipt, a listing), so besides http(s) only a dex folder or a .jsonl file is read (ledgers kept on one machine), never any other local file.

ledgdex.dex.http_get(url, limit=None)

The bytes at an http(s) address, at most limit (default MAX_BYTES) of them.

ledgdex.dex.load_root(dex)

The root ledger named in config.json ("ledgdex": {"root": SOURCE, "root_id": ID}), or None.

An address can start serving another ledger (its hosting or DNS changes hands), so the root is pinned by ledger id: the first time it is read, its id is written to "root_id" (trust on first use), and from then on a root of another id, or a broken one, is refused. A root that rotates or recovers its key keeps its id. The last root read is kept in the dex folder: when the address cannot be read, work goes on with it, and an address serving an older copy (which could hide a revoke or a recovery) is ignored for it.

ledgdex.dex.keygen(name)

Write a new secret key to ~/.ledgdex/NAME.key (mode 600) and return its public key.

ledgdex.dex.load_key(name)

ledgdex.dex.find_key(pub)

ledgdex.dex.signer(led, owner_only=False)

The local secret key to append to led with: an active device key when this machine has one, else the owner key. owner_only: the owner key itself (owner-only types, and messages sent to other ledgers, which carry the self's identity).

ledgdex.cli: The command line, also callable from Python.

ledgdex.cli.main(argv=None)

ledgdex.cli.parser()

ledgdex.cli.next_at(led, secret)

The time to sign a new message with: now, or one second after this key's last message in the ledger (kept or sent) if that is later. A message recorded twice counts once (spec 6.2), so two messages with the same body must differ in "at": two claims for the same offer within one second are two claims, not one.

ledgdex.sig: Ed25519 backends: the cryptography package when present, else the built-in code.

ledgdex.sig.backend   (object: .name, .public_key(secret), .sign(secret, msg), .verify(public, msg, signature))

The Ed25519 backend in use: the cryptography package (name "cryptography") when it is installed and passes a known-answer test, else the built-in code (name "pure"). LEDGDEX_PURE=1 forces the built-in code. Both verify identically.

ledgdex.sig.pure   (object: .name, .public_key(secret), .sign(secret, msg), .verify(public, msg, signature))

The built-in Ed25519 (name "pure"), always available. Not constant time when signing.

ledgdex.sig.sign(secret, msg)

Sign with the chosen backend. The vendored code is not constant time: say so once, unless asked for.

sig.js: Signers for the browser (spec Part III): Web Crypto's Ed25519 when the browser has it and it passes a known-answer test, else the vendored code (ed25519.js). Web Crypto signs in constant time and derives the public key itself, so the secret never goes through the vendored arithmetic. Verification stays with the vendored code everywhere, so every browser judges a ledger the same way. A signer is {name, public, sign(bytes) -> Promise<Uint8Array>}.

vendoredSigner(secret)

webCryptoWorks()

keystore.js: Keeping secrets in the browser, encrypted (Web Crypto). A secret key is stored only sealed with a passphrase: PBKDF2-SHA-256 (600,000 rounds, 16-byte salt) makes an AES-256-GCM key that encrypts it. Bid secrets (amount and nonce, until the reveal) are sealed with a key made from the secret key itself, so they need no passphrase and cannot be read without the key that bid. Nothing secret is stored in the clear.
