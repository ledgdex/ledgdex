CHECKING FOR TAMPERING


A ledger that verifies is consistent and signed by its owner; it is not necessarily the history shown before: an owner can re-sign every entry from some point on. ledgdex check closes that gap with the copies it has seen and the receipts other selves hold.

ledgdex check shop me https://farm.example         # once; exit code 1 on tampering
ledgdex check shop --every 3600                     # as a worker
17 6 * * * cd /srv && ledgdex check shop --json report.json   # from cron
ledgdex workflow shop/ledgdex.jsonl > .github/workflows/ledgdex-check.yml   # daily on GitHub

Errors come with signed proof in .ledgdex-check/proofs/: equivocation (a ledger differs from the copy seen before), receipt_mismatch (a copy has another entry where a receipt holds a signed one), ledger_changed (an address serves another ledger), broken, media_changed, published_differs. Warnings mean something could not be checked: stale, unreachable, needs_root, receipt_bad_signer, receipt_url_mismatch, future_time, media_unavailable, behind.

Check the ledgers you trade with, daily. Example: Check shows a rewrite caught.
